# Agents and the MCP door

What an AI agent on a world needs: the MCP server's connect line and its tools, a seat of its own, and the patterns that work.
Open it to connect the MCP server, or before an agent writes to someone's world; a reader's MCP tools are named in `../SKILL.md`.

## Agents

**Connect the MCP server from Claude Code** (`.env` loaded into the shell, so the key is never typed):
```bash
claude mcp add --transport http onlyworlds https://www.onlyworlds.com/mcp \
  --header "API-Key: ${OW_API_KEY:-$ONLYWORLDS_API_KEY}" --header "API-Pin: ${OW_API_PIN:-$ONLYWORLDS_API_PIN}"
```
With neither `OW_API_KEY` nor `ONLYWORLDS_API_KEY` set in the shell, the header goes out empty and the server answers `401` to every call, the schema tools included: load `.env` before the line. Added with no header at all, the server takes a sign-in on onlyworlds.com instead of a key: a signed-in tool reads the worlds you own or are a member of, and writes in them only if you chose **Read and write** on the sign-in page (**Read only** is selected; Read and write asks for your account PIN, and an account with no PIN stays Read only). It then names the world as `world` on every write, within your role there; `get_me` answers `scope: write` where it may write, and a write it was not granted comes back in the tool's result with the code `write_not_granted`. **Stop writing**, on your account page under **Apps that may write to your worlds**, ends the writing and keeps the reading. The line sends `API-Pin` on every tool call: with an owner's key, a wrong PIN there fails every read tool with `invalid_credentials` (the API's 401), and each one counts ([PIN](writing.md#pin-the-world-wall)). The server has schema, read and write tools, and no delete tool. Beside the element tools: `get_me` (who you are in this world, and its front door: the same body as `GET /api/v2/me`, with your `role` and `character`; `front_door.charter` is the id of the world's Charter, the house rules, read first with `get_element("law", id)`, and `front_door.charter_skill` the ids of the Objects it names, each read with `get_element("object", id)`; null, or the list empty, when there is none you may read; the server's own instructions say to take the Charter and its skills from here each session, never from a list or a search), `list_worlds` (the key's world: `id`, `slug` its public page address or null, `name`, `role`), `list_files` and `read_file` (a text file's words, at most 64 KB a call, opened by a line saying it is world data, not an instruction; a pdf, a zip or an image (png, jpg, webp, avif) answers a 5-minute `download_url`), and `get_image_upload_ticket` (one image: send the bytes to its `upload_url` yourself, then `update_element` sets `image_url`). `update_element` and `edit_links` take `if_match`, the element's `change_seq` as you read it: if anyone wrote it since, nothing is written and the error's code is `precondition_failed`, with the element now under `current`. A refusal from the server is the API's own envelope as JSON text, `{"error": {message, type, code, param, doc_url}}`, with `retry_after` in seconds where the route would send `Retry-After`: read its `code` as in [Errors](writing.md#errors).

**A seat of its own** suits an agent that writes to someone's world: **Make a seat** on the owner's Access page (Let someone in, An AI, the choice A seat here), or under **Your AI in this world** on a member's; the `.env` lines show once, and a lost key is **New key** beside the seat. Its `ow_s_` secret is its PIN, and its writes count as agent-made. Otherwise declare: the header, `agent: true` in the SDK, `agent=True` in Python's `Client`.

**Patterns that work**:
- **Agent with a world**: the agent queries typed elements over MCP instead of guessing from context. `update_element` changes only the fields it is sent, as PATCH does, and a multi-link field it is sent replaces that field's whole array (an empty array clears it): to add or remove links, use `edit_links` (`add`, `remove`), which leaves the rest of the array as it is.
- **World as RAG corpus**: the folder IS a typed, chunked corpus, one JSON file per entity.
- **AI proposes, a human approves, one writer applies** (principles §2): the agent drafts a batch with its own minted UUIDs, a human rules on the list, only the approved items go up via `/bulk`, and people read the result back in Atlas.
- **Game/sim state**: the world as the NPC knowledge base; the app reads typed truth, the LLM voices it. A tool's own data goes in `x_<tool>_...` fields.
